# Pip-Boy touch lists and tabs

[design, #2436] Touch points retain their own custom pointer and projected render-target coordinates. They never create mouse/key hardware events. The mobile wrapper remains the sole raw touch reader. Its native-menu ingress must work with the optional hotbar disabled; bar visibility and hotkey assignment remain optional.

| Contact | Sticky intent | Result |
|---|---|---|
| Short stationary tap | Pending | Release through the real painted tile target or existing Bevy click, with one action owner |
| Mostly vertical travel beyond 12 logical pixels | Scroll | Project the original pane and motion into canvas units; send native wheel steps and cancel click |
| Mostly horizontal travel beyond 12 pixels | Assign | Existing guarded inventory-row/hotkey drop route |
| Stationary hold for 450 ms | Assign | Deliberate assignment drag; a prior vertical scroll never becomes assignment |
| Cancel, overlay, loading/device capture, closed/page/frame/image/flat-geometry change | Canceled | Clear queued points, projected frame, click ownership and partial wheel remainder |

[observed: pipboy.rs, tiles/*_menu.rs] Previously the touch bridge emitted no Scroll action. Native tile pages read only the physical pointer, so projected mobile taps also missed their tab/list actions. TouchPointerPlugin now owns the same production PreUpdate drive route used by PipBoyPlugin and headless composition fixtures. A native target uses its actual takes/hit checks and the native command route on release; the Bevy pointer is canceled for that contact. Hand-built nodes keep their existing click observers. A held/edge physical mouse retains the native page's single pointer, and controller selection rejects the mobile route.

[design] Source-owned WheelFrame is stamped with page/tab/frame and cleared each picking frame. Native ITEMS MenuModel, STATS View and DATA list/pane logic consume it alongside their original physical wheel path. It is not broadcast as a fabricated global MouseWheel. The corresponding PointerInput::Scroll is still emitted for the picking route. Maps do not turn a vertical browsing swipe into zoom; map navigation is separate. Fractions stay with the contact, whole canvas wheel steps are bounded, and lifting/canceling discards leftovers.

[qualification] The packing/hotbar owner supplies OverlayCapture publication and default-disabled native-menu ingress. Scroll is not qualified end to end until those real wrapper changes are composed. Three production gesture CPU tests passed; App/World tests for real inventory/model outcomes, actual picking tab clicks, native tile tabs, assignment guards, projection/order and cancellation are authored. ARM compilation is not execution, and neither substitutes for phone behavior.

[design, release ownership] A native contact records the actual event tile, reachable clipped bounds and painted row identity at press. Inventory uses the existing RowGuard plus folder/category; Stats and DATA use the keys their existing tile writers own. Release is admitted only for the same target, with another check immediately before native input is applied. A redraw in that Update cannot substitute a new row. The initial inventory selection intent is kept: hover after press cannot upgrade a selection into item use. Existing FreshMenu and close/page/frame/image/geometry admission retires old contacts; no MenuModel nonce, constructor, debug or saved-format changes are introduced.

[design, physical priority] The shared production pointer plugin observes actual mouse held/edge state and actual wheel messages before its pointer boundary. Physical intent cancels only the mobile operation and its queued projection. Touch wheel publication and native model consumption both refuse that frame; the physical wheel retains the physical pointer's pane. Mouse state and events are neither cleared nor fabricated. A fresh pure-touch contact works after physical activity ends.

[qualification, followup] The native guard regressions use actual tile page repaint between press and release, adjacent-tab jitter below the drag threshold, first-select/next-use behavior, and valid fresh taps. The physical priority regression uses opposite list/description anchors, held left/right buttons, edges and a real wheel-only baseline. These App tests are authored and unrun until the combined check/execution receipt; static counterexamples explain why the unguarded source is unsafe, without claiming a run.

[design, selected-row actions] Native Equip, Drop, Repair and Mod buttons retain the actual painted selected RowGuard, not merely the button tile. The current model must still have that row selected when release is admitted. Other inventory targets also retain folder/category context. A script-visible native Equip target regression changes and repaints the selection between press and release while keeping the same button tile/bounds; the old release acts on nothing, and a fresh valid press uses only the currently selected item once.

Native touch action buttons retain their press-time semantic context too. Inventory Equip/Drop/Repair/Mod capture the painted selected RowGuard and current folder/category, so a selection change or repaint cancels the deferred action. STATS hints retain their effective limb/status (the hint itself becomes hover before it acts). DATA buttons retain their painted action kind, selected record and list/filter group plus live selection, active quest, Travel marker and Place Marker/custom-marker context. Geometry alone cannot authorize an action on a newly selected subject. These checks do not change physical mouse/keyboard/controller delivery.

Three additional native App regressions cover Inventory action-button repaint, STATS Stimpak limb repaint, and DATA selected-record/action-kind repaint (both cases), each followed by a fresh valid tap that emits exactly one original native action. These tests are authored but uncompiled/unexecuted in this leaf; parser-only validation does not qualify runtime behavior.
