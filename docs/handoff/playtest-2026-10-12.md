## 1. How the work was run (repeat this on another machine)

- One sibling worktree per workstream: `git worktree add ../NVForever-<name> -b <branch> origin/main`.
  Never edit the main checkout from a workstream.
- Build folders copied, never shared: copy an existing `engine/target` (and `target`) to a new
  folder (on this machine `F:/nvf-target/<name>-engine` / `-root`) and build there with
  `CARGO_TARGET_DIR`. A cold engine build is long and about 4 GB.
- Game data is read-only (`<Steam>/Fallout New Vegas/Data`). Lab env: `FNVLAB_DATA_DIR`,
  `FNVLAB_GOLDENS_DIR` (goldens are private, not in the repo).
- Game window runs take two locks by `mkdir` (paths in `tools/smoke`, overridable with
  `NVF_SMOKE_LOCKS`); release them in an exit trap. A lock left by a dead run blocked all
  agents once (00:43, 2026-10-12): the smoke runner now says who holds a lock and how old it is.
- Smoke tests: **use `python tools/smoke run`** (PR #227, merged). It picks the scenarios the
  changed files call for, prints one line per scenario, keeps logs in `target/smoke/`, and
  lists the push checks that apply. Read only its summary. New checks are `[[scenario]]`
  entries in `tools/smoke/scenarios.toml`, not CLAUDE.md prose.
- Usage is tight: at most ~4 agents at once, checks once at the end, no full lab run unless a
  scored crate changed, one before/after frame per picture check. Each agent keeps its scratch
  files in its own subfolder (shared scratch files collided twice).
- Agents open PRs and never merge; the coordinator reads the core of each diff, resolves
  conflicts (usually `docs/owner-review.md` appends: keep both, newest last; and
  `fnv-ai/src/carry.rs` `Agent` fields / `engine/nvforever/src/residents.rs` `Resident`
  fields, where several workstreams add fields: keep all), builds the touched crates and
  engine clippy after a conflict, then merges.
