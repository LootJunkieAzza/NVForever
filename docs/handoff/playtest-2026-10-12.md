## 1. How to work (any machine)

- One sibling worktree per workstream: `git worktree add ../NVForever-<name> -b <branch> origin/main`.
  Never edit the main checkout from a workstream.
- Own build folders per workstream (`CARGO_TARGET_DIR`), copied from an existing build: a cold
  engine build is long and about 8 GB (engine and root targets each). Never share one target
  between branches being built at the same time.
- Game data is read-only (`<Steam>/Fallout New Vegas/Data`). Lab env: `FNVLAB_DATA_DIR`,
  `FNVLAB_GOLDENS_DIR` (goldens are private, not in the repo).
- **Smoke tests: `python tools/smoke run`** (picks the scenarios the changed files call for; one
  line per scenario; logs in `target/smoke/`). New checks are `[[scenario]]` entries in
  `tools/smoke/scenarios.toml`, never CLAUDE.md prose. Never loosen an expectation; mark it
  `known_failing` with the reason. Game runs take two `mkdir` locks (`NVF_SMOKE_LOCKS` on
  other machines).
- A machine loaded by 3–4 agents makes start-up slow (the add-on packs' message boxes and
  scripts ready only after 14–17 s); timed test aids can then land late. Re-run a failure
  alone before blaming a branch.
- Agents open PRs and never merge; a coordinator reads the core of each diff, resolves
  conflicts (`docs/owner-review.md` appends: keep both, newest last; `fnv-ai/src/carry.rs`
  `Agent`/`Ai` fields and `engine/nvforever/src/residents.rs` `Resident` fields: keep all),
  builds and runs engine clippy after a conflict, then merges.
- The common rules given to every agent (this machine's copy): `C:\fnv-private\agent-common-brief.md`.
