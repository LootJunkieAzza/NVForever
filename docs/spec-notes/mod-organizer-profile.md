# Spec note: a Mod Organizer 2 instance and profile

Clean-room description in plain language of the files NVForever reads when it merges a Mod
Organizer 2 profile itself (#1526). Confidence tags: **[documented]** cites a public source,
**[observed]** was checked on this host, **[hypothesis]** needs verification.

Sources, all public MO2 sources read as documentation (never copied):

- instance paths and settings: `modorganizer/src/settings.cpp`, `PathSettings::mods`,
  `profiles`, `overwrite`, `base`, `getConfigurablePath`, `resolve`
- the profile and its mod list: `modorganizer/src/profile.cpp`,
  `Profile::doWriteModlist` (write) and `Profile::loadModlist` (read)
- the plugin lists: `modorganizer-game_gamebryo/src/gamebryo/gamebryogameplugins.cpp`,
  `GamebryoGamePlugins::writeList`
- the merge itself: `OrganizerCore::beforeRun` / `fileMapping` (usvfs), as cited in
  `crates/fnv-install/src/mo2.rs`

## The instance folder

A portable instance is the folder holding `ModOrganizer.exe` and `ModOrganizer.ini`; a
global one lives under `%LOCALAPPDATA%\ModOrganizer\<name>` and MO2's current one is named
by `CurrentInstance` under `HKCU\Software\Mod Organizer Team\Mod Organizer`
[documented: `InstanceManager::currentInstance`]. NVForever is given the folder directly
(`--mo2`), so only the INI's keys matter.

Keys [documented: `PathSettings`]:

- `[General] selected_profile` — the open profile's name.
- `[Settings] base_directory` — `%BASE_DIR%`, defaulting to the INI's own folder.
- `[Settings] mod_directory` — default `%BASE_DIR%/mods`.
- `[Settings] profiles_directory` — default `%BASE_DIR%/profiles`.
- `[Settings] overwrite_directory` — default `%BASE_DIR%/overwrite`.

Values are QSettings strings: `%BASE_DIR%` is substituted, and `\\`, `\"`, `\xHH` and the
other Qt escapes are read (the engine already had `mo2::ini_value` for this). MO2's
substitution is all `PathSettings::resolve` does — it replaces `%BASE_DIR%` and leaves any
other value as written [documented: `PathSettings::resolve`, `getConfigurablePath`], so a
relative value would be relative to MO2's own working directory. NVForever instead joins a
relative value onto the instance folder, the reading that makes a hand-written INI work
[hypothesis: no instance on this host sets one].

The profile's files are `<profiles_directory>/<name>/modlist.txt`, `plugins.txt` and
`loadorder.txt`.

## `modlist.txt`

[documented: `Profile::doWriteModlist`; observed: this host's test fixtures and the
maintainer's reports]

- First line: `# This file was automatically generated by Mod Organizer.` + CRLF.
- Then one line per **regular** mod, in **reverse priority order: the highest priority
  first** (the write loop walks the priority map backwards), and the loader inverts the
  order back. Automatic rows (separators, backups) are not written.
- Prefix: `+` enabled, `-` disabled, `*` a "foreign" mod (the game's own files, on).
- The separator between prefix and name is not part of the name; a disabled mod stays in
  the file so its position survives.
- `overwrite` is a folder, not a list entry in current MO2: it is written as the highest
  priority in memory [documented: `loadModlist` gives it `size - 1`].

Consequence for a merge: read the file top to bottom for the display order, apply the
enabled mods' folders from the **last** enabled line up (lowest priority first) so a
higher one replaces a lower one's file, then the overwrite folder last.

## `plugins.txt` and `loadorder.txt`

[documented: `GamebryoGamePlugins::writeList`]

- First line: the same MO2 header + CRLF.
- `plugins.txt`: only the **active** plugins, one per line, sorted by the plugin list's
  priority (load order, first loaded first), encoded in the system's ANSI code page.
- `loadorder.txt`: **every** plugin in the same order, encoded UTF-8.
- Older games' lists (and other managers') put `*` before an active name; a `*` is never
  part of a file name and is stripped if seen.
- A profile MO2 has never written has neither file.

Nominal New Vegas load order still applies on top: the first master first, masters before
their dependants; the engine's `fnv_esm::loadorder` refuses a list that breaks it and says
why.

## The profile's archive list

[documented: `MainWindow::saveArchiveList`, `FalloutNVDataArchives::archives`/`writeArchiveList`]

- `archives.txt` in the profile: one **ticked** archive name per line (CRLF), from MO2's
  Archives tab, in the tab's display order; nothing else. MO2 writes it whenever the
  archive list or mod priorities change, so it is the profile's live archive choice.
- The same ticks are also written into `[Archive] SArchiveList` of the applicable
  `fallout.ini`: the profile's own file when local settings are on, else the one under
  `Documents\My Games\FalloutNV`. MO2 joins the names with `, `.
- An empty `archives.txt` (a profile made by hand, or one MO2 has not opened) means the
  game's list comes from the INI; with neither, MO2 falls back to the six vanilla archives.
- A `.bsa` in a mod folder is only loaded when its name is in this list; usvfs makes the
  file visible in `Data`, but the game loads archives by name. NVForever mounts exactly the
  listed names, taking each from the highest layer that has the file.

## What usvfs merges, in order

[documented: `OrganizerCore::fileMapping`, usvfs' mapping priorities]

The program sees `Data` as: the game folder's own files, then each enabled mod's folder by
priority (higher priority replacing lower), then the overwrite folder. NVForever implements
the same precedence for loose files, for looking a plugin up, and for finding the file an
archive name stands for (a mod's copy of a base archive replaces the game's). Which archives
are mounted at all is the profile's archive list, above.
