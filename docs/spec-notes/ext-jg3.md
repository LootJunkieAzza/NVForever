# JohnnyGuitar NVSE, batch 3 (2026-11-01, #1007)

Effect shaders' traits and textures, media sets' traits, casinos' chips and winnings,
terminals' menu items and the quest script delay, in
`crates/fnv-game/src/nvse_jg3.rs`. Sources: the GECK wiki export [documented: the page
named]; the record layouts from `schemas/fnv` (xEdit wbDefinitionsFNV.pas). Probed in
the game as set jg3 (`tools/capture/jip_probes.py`, lab scenario `L5.ext.jg3`; JohnnyGuitar
with xNVSE 6.4.9, 2026-11-08); "jg3 row" below names that set's rows. Setters change the
record for the session, read by the getters. Tests: `crates/fnv-game/tests/jg3.rs`.

| Function | NVForever |
|---|---|
| GetEffectShaderTraitNumeric, SetEffectShaderTraitNumeric `shader trait [value]` | EFSH DATA by the page's trait table, 0 flags to 46 scale key 2 time; the blends and Z tests (1-3, 23-27) as their numbers [documented: the table; the fields and enum numbers: schemas/fnv/effects.json]. The fill and edge colours (4, 14) read as one number, red × 65536 + green × 256 + blue [observed: jg3 efsh.trait.nuke.4, .nuke.14, .cateye.14]. Trait 47, past the table, reads the next DATA field, colour key 1, packed the same way [observed: jg3 efsh.trait.nuke.47]; past 47 is not known (0 here), and -1 reads 0 [observed: jg3 efsh.trait.nuke.-1]. The setter returns 1 when done [documented: "returning 1 on success"] and takes every trait the getter reads, not only the 0-42 its page lists [observed: jg3 efsh.set.nuke.43, .nuke.47]; flags and enums keep whole numbers [observed: jg3 efsh.set.nuke.0, .nuke.1]; a colour set as one number reads back as given [observed: jg3 efsh.set.nuke.4], kept to 24 bits [hypothesis] |
| GetEffectShaderTexturePath, SetEffectShaderTexturePath `shader id [path]` | 0 fill (ICON), 1 particle shader (ICO2), 2 holes (NAM7); "" for none [documented: the table; the subrecords: xEdit EFSH]. Another id fails the getter's call [observed: jg3 efsh.tex.nuke.3, .nuke.-1, "script call failed"] |
| GetMediaSetTraitNumeric, SetMediaSetTraitNumeric `set trait [value]` | 0 the type (NAM1: -1 none, 0 battle, 1 location, 2 dungeon, 3 incidental) [observed: jg3 mset.num.bttl.0, .corp.0, .freeside.0], 1-6 the dB values, 7-12 the boundaries, 13 the enable flags (PNAM), 14-17 the times (DNAM-GNAM); 0 for a missing subrecord or another trait [documented: the page's table names each subrecord; observed: jg3 mset.num.corp.18, .corp.-1]. The flags (13): CorpRuins (PNAM 63) read 9.39949e+08, kept after a set and restore, while the battle set (PNAM 80) and Freeside (0) read their bytes [observed: jg3 mset.num.corp.13, mset.set.corp.13, .bttl.13, .freeside.13]; the getter may read four bytes where PNAM is one [hypothesis]. NVForever reads the byte, as what fills the other bits is not in the record |
| GetMediaSetTraitString, SetMediaSetTraitString `set trait [path]` | 0-5: NAM2-NAM7, the sound paths [documented]. The record's path reads under `Data\Music\`, a missing one "" [observed: jg3 mset.str.corp.0-5, .dung.0, .dung.1, .dung.3]; a path a script set reads back as given [observed: jg3 mset.setstr.corp.0]. Another trait fails the getter's call [observed: jg3 mset.str.corp.6, .corp.-1] |
| GetMediaSetTraitSound, SetMediaSetTraitSound `set trait [sound]` | 0 HNAM (intro, daytime), 1 INAM (outro, nighttime) [documented]; the setter takes a sound form only: none and other forms change nothing [observed: jg3 mset.setsound.bttl.none, .notsound]. The getter on a set without the subrecord crashed the original game (CorpRuins, trait 0) [observed: jg3, 2026-11-08; not probed since]; NVForever reads none |
| GetCasinoChip, SetCasinoChip `casino [chip]` | the casino's chip (CSNO DATA currency) [documented: the page; the field: xEdit CSNO]; the setter takes a CHIP form, another form changes nothing [observed: jg3 casino.setchip.tops.notchip]. The tables (blackjack, roulette, slots) play with the chip set (`casino::chip`) |
| GetCasinoWinnings, SetCasinoWinnings `casino [chips]` | the player's net chips won at the casino (`casino::add_earnings`, blackjack.md §4) [documented; observed: jg3 casino.setwin.tops.1234, .neg read back]; setting it also raises the winnings level the casino's scripts read, as a game's round does [hypothesis]. A fraction (2.7) as the argument does not compile in the game [observed: jg3 casino.setwin.tops.frac]; NVForever's compiler takes it (not followed: no rule yet for which int parameters refuse a fraction) |
| GetTerminalMenuItemCount `terminal` | the number of menu items (ITXT) [documented] |
| GetTerminalMenuItemText, SetTerminalMenuItemText `terminal textID item [text]` | 1 the item's line (ITXT), 2 its result text (RNAM) [documented]. textID 0 fails the getter's call; 3 read "" on an item whose result text is empty [observed: jg3 term.text.v34.0.0, .v34.3.0], so whether 3 reads the result text is not known (NVForever: ""). An item past the list crashed the original game [observed: jg3, 2026-11-08; not probed since]; NVForever reads "" |
| Get/SetTerminalMenuItemNote, …Submenu, …Flags `terminal item [form / flags]` | the item's display note (INAM), sub menu (TNAM), flags (ANAM: 1 Add Note, 2 Force Redraw) [documented]. The flags setter keeps the whole number, not only those two bits [observed: jg3 term.setflags.east.0.7, .v34.4.6], as a byte [hypothesis]. A note setter takes a NOTE, a sub menu setter a TERM; another form changes nothing [observed: jg3 term.setnote.v34.0.notnote, term.setsubmenu.v34.4.notterm]; none clears the entry [hypothesis: not probed, unlike SetMediaSetTraitSound's none]. GetTerminalMenuItemNote with an item past the list crashed the original game [observed: jg3, 2026-11-08]. The changes reach the terminal screen: the listed lines, the result text, the note shown and given, and the sub menu opened (`terminal::item`) |
| GetQuestDelay `quest` | SetQuestDelay's delay for the session [observed: jg3 quest.setdelay.legion], else the record's (DATA) as it stands: 0 reads 0, not the 5 s the quest then runs at [documented: the page; observed: jg3 quest.delay.vcg02]; a DATA without a delay reads 0 [hypothesis] |

Not in this batch: SetProjectileSound and SetExplosionSound (nothing reads a projectile's or an
explosion's sounds yet, neither a getter nor the engine), GetWorldspaceEncounterZone and SetWorldspaceEncounterZone (WRLD XEZN is
not in the schema yet), HSVtoRGB and RGBtoHSV (outputs into script variables), GetRGBColor
(how the three channels pack is not documented), AddTerminalMenuItem, RemoveTerminalMenuItem
and RefreshTerminalMenu (they change the list's length while the menu shows; a design of
their own). The engine's effect shaders do not read a changed trait or texture yet; the page
warns that most changes do not show while the shader plays.
