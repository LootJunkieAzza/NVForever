# fnv-parity-lab

Differential-testing lab: compares recorded behaviour of the original game (the
**oracle**, stored as JSON goldens) with this engine (the **candidate**, the `fnvtool`
CLI) and writes reports an agent or a human acts on. Python 3.11+, standard library only,
kept separate from the engine code. Agent rules: [AGENT.md](AGENT.md).

## Quick start

```bash
cargo build --release -p fnvtool                    # from the repo root
cp parity-lab/lab.local.example.json parity-lab/lab.local.json   # then edit the two paths
cd parity-lab
python -m fnvlab list
python -m fnvlab run                                # writes runs/latest.json + runs/latest.md
python -m fnvlab baseline                           # HUMAN ONLY: accept current results
```

Self-test and demo (synthetic data, a deliberately buggy fake candidate):

```bash
python -m unittest discover -s tests -v
python -m fnvlab --config selftest/lab.json run     # shows pass, fail, error and a redacted holdout
```

## Concepts

| Term | Meaning |
|---|---|
| Oracle | Ground truth from the user's own install or a trusted tool, as a JSON golden (or `inline` for invariants such as "rewrite is byte-identical") |
| Candidate | `fnvtool …` printing JSON in the golden's schema (`docs/cli-contract.md`) |
| Scenario | JSON entry: `id`, `layer`, `oracle`, `candidate.argv`, `comparator`, `tags`, optional `holdout` |
| Holdout | Failure details are redacted from reports, `list` and `next_work`; only a human at a terminal can `--reveal` (writes `runs/revealed.md` only) |

## Configuration

`lab.json` is committed and contains no private paths. Private values come from
`lab.local.json` (gitignored overlay) or `FNVLAB_<VAR>` environment variables:
`candidate`, `data_dir`, `goldens_dir`, `schema_dir`. `{var}` placeholders expand inside
scenario argv and golden paths.

## Comparators

| Kind | Use | Options |
|---|---|---|
| `exact` | deep diff | `select` (pointer), `abs_tol`, `rel_tol`, `ignore_paths`, `subset` (extra candidate keys allowed) |
| `keyed` | record sets | `select`, `key` (field or list), `fields` (default: all oracle fields), tolerances; reports missing / extra / changed |
| `sequence` | ordered traces | `select`, `fields`, tolerances; score = matching prefix, reports first divergence |
| `image`, `distribution` | planned | currently report `error` |

Scores are in [0, 1]. Status: `pass` (no failures), `fail`, `error` (oracle, candidate or
harness problem — never a crash). Each failure has a stable ID: SHA-1 of
(scenario, kind, path), first 12 hex digits.

## Reports and exit codes

`runs/latest.json` (schema `fnvlab.run/1`) and `runs/latest.md`: per-layer pass counts
and mean scores, regressions, `next_work` (lowest layer first, then worst score; holdouts
never listed), details per scenario. A timestamped copy goes to `runs/history/`.

Exit codes: 0 ok · 1 regression vs `runs/baseline.json` · 2 `--strict` and not all pass ·
3 configuration error.

## Layer 1 scenarios

Generated by `tools/gen_layer1_scenarios.py` into `scenarios/`:

- `layer1_esm.json`: inventory (keyed by FormID), header, stats, round-trip for 10 masters
- `layer1_bsa.json`: listing (keyed by path, SHA-256 of decoded contents), header, round-trip for 15 archives
- `layer1_bsa_local_only.json`: the same for the 7 archives over 400 MB (tag `needs-local-capture`)
- `layer1_xedit.json`: inventory vs FNVEdit exports (tag `needs-local-capture`)

Goldens are produced by `tools/capture/` and must stay out of any public repository.
