A performance and fix release on top of v0.8.0: everything merged since v0.8.0 (2026-11-18),
19 pull requests. The main news is **far less hitching when NPCs come into view**, **faster
starts after the first**, and **Linux builds that run on the Steam Deck again**.

**You need your own copy of Fallout: New Vegas (1.4.0.525, base game + all DLC).** No game
data is included. Unpack anywhere outside the game folder and run `nvforever-launcher.exe`
or `nvforever.exe` (or `nvforever.cmd`; `./nvforever.sh` on Linux). The first start asks
for your game folder and remembers it. `README-release.md` in the archive explains the
rest. NVForever never writes into the game folder or `Documents\My Games\FalloutNV`; its
own home is `Documents\My Games\NVForever`.

**Reports** stay opt-in: nothing is sent unless you chose **Send reports** at the first
start, and Settings → Gameplay → Reports turns them off or deletes what was sent.

## Performance

- **NPCs coming into view no longer stall the frame.** Drawing an NPC used to cost up to
  70 ms in one frame; it now stays under 7 ms. Their parts are prepared whole on worker
  threads (#3073), a creature's first appearance has no main-thread spike (#3093), the
  weapon's muzzle comes from its own part and FaceGen offsets are made ahead on a worker
  (#3101).
- **Faster starts after the first**: composed shaders, the graphics driver's pipeline cache
  and a list of the pipelines asked for are kept between runs, so the second start builds
  almost nothing (#3079). The residents in view are drawn behind the start's loading screen
  instead of after it (#3081).
- Loading: static models read their stored tangents instead of computing them, and the
  start's models are prepared on the read pool while the loading picture shows (#3087).
- Cell crossings in the open world: no more 50-120 ms frames with mesh blend on; cheaper
  level sync, distant water and read-ahead (#3070). Cells that left the read-ahead ring are
  freed on a worker thread (#3088).
- The world's cells sit under one parent, so moving through the world no longer
  recomputes the positions of cells that did not change (#3071).

Measured on the developers' stress tour (Goodsprings to South Vegas, New Vegas Steel and
Camp McCarran and back, two laps, a GTX 1050 laptop): the time spent drawing NPCs went from
about 900 ms to 137 ms, the slowest 1 % of frames from 48 ms to 43 ms, and a second start
from 9.2 s to 7.1 s to the end of the loading screen.

## Linux

- **The Linux build runs on the Steam Deck and other systems with glibc 2.39 again.** The
  v0.6.0-v0.8.0 Linux programs asked for glibc 2.43 and the system refused them before a
  window or log appeared. The release now builds on Ubuntu 24.04 and checks the glibc each
  program asks for before publishing (#3068).

## Fixed since v0.8.0

- **AI**: an unreachable package place names the door that closes the way; doors that are
  not in the world no longer bar anything (#2405, #3054). An NPC's package aimed at an
  intercom finds its lines: talking activators listen as their talking actor (#3051).
  Package queries and merchant clearing use the actor's own context (#2820).
- **Combat**: standing radscorpions keep apart, and creature melee holds to the attack
  clip (#2971).
- **Scripts**: loaded script callbacks and owned runtime handles are found by identity
  (#2877); Windows script cursor moves are acknowledged before positions are published
  (#2884); a test holds that an AddItem on a placed container not yet read is kept (#3047).
- **Graphics**: `SetMaxAniso` levels reach the cached texture samplers (#2895). Water
  effects: caustics, river flow and readable shallows, as an enhanced-look switch (#3008).
