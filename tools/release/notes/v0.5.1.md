A hotfix for v0.5.0: **heavy stutter in long play sessions after nightfall**. About 20
minutes into a session, once the game clock reached night, frames dropped to 30 fps and froze
for 100 to 800 ms every few seconds, wherever you were, until the game was restarted
(#897).

**You need your own copy of Fallout: New Vegas (1.4.0.525, base game + all DLC).** No game
data is included. Unpack anywhere outside the game folder and run `nvforever.exe` (or
`nvforever.cmd`; `./nvforever.sh` on Linux). The first start asks for your game folder and
remembers it, and the game opens on the main menu. `README-release.md` in the archive
explains the rest. NVForever never writes into the game folder or
`Documents\My Games\FalloutNV`; its own home is `Documents\My Games\NVForever`.

## Fixed since v0.5.0

**The night stutter** (#893, #898)
- The cause was GPU memory: late in a session, each frame's short-lived upload memory spilled
  into a fresh 128 MB block that was freed again at once, several times a frame, and Windows
  zeroed and paged in every one while the game waited. Emptied blocks are now kept for reuse.
- The sky, its clouds and the eye-adaptation pass no longer remake GPU buffers every frame,
  lights are clustered on the CPU, and material data goes to the GPU in smaller pieces (render
  time 30 to 40 % lower).
- Measured over two laps of the Mojave with 8x anti-aliasing: stalls of 100 ms or more in the
  renderer went from 37 to 64 a run to none, visible hitches from 10 to 19 a run to 0 to 2,
  and the slowest 1 % of frames from 65 ms to 52 ms.

**Also merged**
- Radiation markers fall off with distance instead of irradiating at full strength across
  their whole radius (#895).

If you still see stutter, the settings page's Anti-aliasing at 4x (the default) is the
lighter choice. Report it with the issue forms on GitHub, with your graphics settings and
the run log from `Documents\My Games\NVForever\logs`. Never attach game files.
